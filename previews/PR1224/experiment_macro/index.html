Define experiments using @experiment

Say you have a model of a brain circuit, and you would like to see its outputs with various sets of parameters. The @experiment macro provides an easy interface for iterating on a problem by changing its parameters, initial conditions, and timespan.

First let's create a circuit and then a simulation.

@graph g begin
    @nodes begin
        Brainstem = NGNMM_theta()
        Cortex = Cortex(
            N_wta=20, 
            N_exci=5, 
            density=0.05, 
            weight=1.0, 
            I_bg=4, 
            G_syn_inhi=4.0, 
            τ_inhi=70, 
            G_syn_ff_inhi=1.5
        )
    end
    @connections begin
        Brainstem => Cortex, (weight = 20)
    end
end

tspan = (0., 500.)
prob = ODEProblem(g, [], tspan)

Modifying parameters

Let's say we apply a drug whose known effect is to scale the timescale of the GABA synapses. Let's also say that this effect is limited to the cortex. Then we can write:

prob_drugged = @experiment prob begin
    @setup begin
        scale = 2.0
    end

    GABA_A_Synapse in Cortex, τ₂ -> τ₂ * scale
end

Inside the experiment macro, the @setup block is optionally used to define variables.

The next line gives a rule for changing the parameters of the problem. This has two parts:

  1. Blox selection: GABA_A_Synapse in Cortex is used to select all the GABA_A_Synapse inside the graph for Cortex (reference the API to see the full list of recognized selections)
  2. Parameter modification: τ₂ -> τ₂ * scale sets the τ₂ parameter of all of these synapses to its original value times scale. This should be read as a function.

Any number of these parameter modification lines may be included inside the macro.

Note also that prob_drugged is a copy of the original prob; if we wanted to simulate the original prob, we could.

Modifying connection weights and synapse parameters

You can also target connections directly using a => pair. This updates both the connection weight property (if the argument name matches, e.g. weight) and any matching parameter on all intermediate synapse/receptor blox involved in that connection:

prob_scaled = @experiment prob begin
    @setup begin
        scale = 2.0
    end

    # Scale the weight of every connection from Brainstem to Cortex,
    # and also any matching parameter on intermediate synapses:
    Brainstem => Cortex, weight -> weight * scale
end

To restrict the update to a specific synapse type only:

prob_drugged = @experiment prob begin
    @setup begin
        scale = 2.0
    end

    (GABA_A_Synapse ∈ (Brainstem => Cortex)), τ₂ -> τ₂ * scale
end

Both Brainstem and Cortex here may be composite blox (brain regions) or simple blox. The macro traverses the flat graph to find all connections between their constituent neurons.

Selecting blox by tag

Every blox has a tags::Set{Symbol} field, which marks a subset of blox of one type without defining a new type. Set it with the tags keyword argument when constructing a blox. Connection rules forward tags to the synapse, receptor and transmitter blox they create, so you can tag specific routes of a circuit:

@graph g begin
    @nodes begin
        itcvm = ITCvm()
        itcdm = ITCdm()
        cem   = CeM()
    end
    @connections begin
        # these GABA-A synapses are γ1-subunit-containing
        itcvm => cem,   HypergeometricRule(; density=0.07, weight=0.1, tags=:gamma1)
        # an ordinary GABA-A projection from the same neurons
        itcvm => itcdm, HypergeometricRule(; density=0.1, weight=0.05)
    end
end

Any blox selection except a bare src => dst pair can be restricted with a where clause. The clause is a Bool expression of tags, the tag set of each candidate blox. For example, a γ1 positive allosteric modulator slows the decay of only the tagged synapses:

prob_pam = @experiment prob begin
    (GABA_A_Synapse where :gamma1 ∈ tags), τ₂ -> τ₂ * 2
end

Because the predicate is ordinary Julia, you get any/all/exclusion for free, and variables from the surrounding scope can be used:

subunit = :gamma1
prob_2 = @experiment prob begin
    (AbstractReceptor where subunit ∈ tags || :gamma2 ∈ tags), τ₂ -> τ₂ * 2  # either tag
    (GABA_A_Synapse where :gamma1 ∉ tags), G_syn -> G_syn * 0.5              # untagged ones
end

A where clause also composes with the composite ((T ∈ composite)) and typed-connection ((T ∈ (src => dst))) selections. Parenthesise the selection before attaching where:

prob_3 = @experiment prob begin
    ((GABA_A_Synapse ∈ (itcvm => cem)) where :gamma1 ∈ tags), τ₂ -> τ₂ * 2
end

The synapses of a connection between two composites belong to the enclosing graph, not to either composite. So select them with the connection form above, not with (GABA_A_Synapse ∈ CeM).

A where line that selects no blox raises an error, so a misspelled tag can't silently turn an intervention into a no-op. Tags on a composite blox are stored on the composite only. They are not copied onto its components, so a where clause, which looks at the simple blox of the flat graph, does not see them.

Modifying initial conditions and timespan

Let's see how to change initial conditions and timespans for the problem. Let's say we want to dose the drug only after an initial warmup period (that is, simulate the undrugged problem for some time t, then apply the drug effect). We also don't want the drugged simulation to run quite as long.

sol_undrugged = sol(prob, Vern7())

prob_drugged = @experiment prob begin
    @initial_conditions sol_undrugged.u[end]
    @tspan (0., 300.)
    @setup begin
        scale = 2.0
    end

    GABA_A_Synapse in Cortex, τ₂ -> τ₂ * scale
end

Drug specifications

Instead of writing parameter changes by hand, a drug can be specified by its concentration and its interactions with receptor targets, each with its own mechanism and potency, and applied to a problem with apply_drug.

drug = Drug(; concentration=30.0, interactions=[
    # γ1-subunit GABA-A PAM, f = 3/4: τ₂ scaled by 1.75 and G_syn by 0.85
    AllostericModulation(; target=Union{GABA_A_Synapse, GABA_A_Receptor_2state}, tags=[:gamma1],
                         potency=10.0, effects=[Effect(DECAY, 100.0), Effect(AMPLITUDE, -20.0)]),
    # competitive antagonism at D2 at C = 3 K_B: dose ratio 4, so K_D2 is multiplied by 4
    CompetitiveAntagonism(; target=MsnD2Receptor, potency=10.0),
    # non-competitive antagonism: amplitude scaled by the unoccupied fraction
    NoncompetitiveAntagonism(; target=NMDA_Synapse, potency=100.0),
])
prob_drug = apply_drug(drug, prob)

Which parameters an interaction changes is set by property_to_parameters below: each receptor type and property lists the parameters it acts on.

NeurobloxPharma.Drug — Type
Drug(; concentration, interactions)

A drug at free brain concentration (nM) with its AbstractInteractions at receptor targets. Apply it to a problem with apply_drug.

NeurobloxPharma.apply_drug — Function
apply_drug(drug::Drug, prob)

The problem prob with the receptor parameters changed by each of drug's interactions.

NeurobloxPharma.AbstractInteraction — Type

A drug's interaction with the receptors of type target (a receptor type or a Union of them, e.g. Union{GABA_A_Synapse, GABA_A_Receptor_2state}) that carry all of tags. potency is the drug concentration (nM) of half-maximal occupancy: at concentration C the fractional occupancy is f = C^n / (C^n + potency^n) with Hill coefficient n. See property_to_parameters for the parameters each property changes.

NeurobloxPharma.AllostericModulation — Type
AllostericModulation(; target, tags=Symbol[], potency, hill_coefficient=1.0, effects)

Modulation of the receptor's response to its transmitter. potency is the modulator's EC50, and each Effect is applied as Emax * f. See AbstractInteraction.

NeurobloxPharma.Agonism — Type
Agonism(; target, tags=Symbol[], potency, hill_coefficient=1.0, effects)
Work in progress

effects are applied as for AllostericModulation, so this does not model the tonic activation an agonist causes. Receptor activation is driven only by presynaptic transmitter, so an agonist needs a transmitter-independent term: e.g. a drug-bound state competing with transmitter in the kinetic receptors (g = G_syn*(O + ε*A), efficacy ε), and two-ligand competition in the D1/D2 ϕ∞. The sigmoid-driven synapses have no occupancy variable, so any agonist term there is only approximate.

NeurobloxPharma.Antagonism — Type

Antagonism: potency is the antagonist's equilibrium dissociation constant K_B (see cheng_prusoff to convert an IC50).

NeurobloxPharma.CompetitiveAntagonism — Type
CompetitiveAntagonism(; target, tags=Symbol[], potency, hill_coefficient=1.0)

Antagonism at the transmitter binding site. It divides POTENCY by the dose ratio r = 1 + (C/K_B)^n (Schild), leaving the maximal response unchanged. Receptors with no POTENCY parameter (the spike-driven synapses) have AMPLITUDE divided by r instead: a transmitter pulse is too brief to displace a pre-bound antagonist. See Antagonism.

NeurobloxPharma.NoncompetitiveAntagonism — Type
NoncompetitiveAntagonism(; target, tags=Symbol[], potency, hill_coefficient=1.0)

Antagonism that does not compete with the transmitter, so it scales AMPLITUDE by the unoccupied fraction 1 - f. See Antagonism.

NeurobloxPharma.cheng_prusoff — Function
cheng_prusoff(IC50, A, EC50_A)

The K_B of a competitive antagonist with inhibitory IC50, measured against agonist concentration A of potency EC50_A.

NeurobloxPharma.Effect — Type
Effect(property::ResponseProperty, Emax)

One measured effect of a drug: its maximal change Emax in property, at saturating concentration, in %.

NeurobloxPharma.property_to_parameters — Function
property_to_parameters(T::Type{<:AbstractReceptor}, property::ResponseProperty)

The parameter(s) of receptor type T that a drug changes when it acts on property, or nothing if T does not map property. See parameter_transform for how they change. POTENCY is the transmitter's potency: an increase lowers its EC50.

† parameter meaning inferred from its name; confirm against the blox docstring.
