Exporting a model to a standalone file

A problem built from a model graph can be written to a single Julia file that runs with neither Neuroblox nor GraphDynamics installed. The file contains the right-hand side of the differential equation as generated code, the initial states, the parameter values and the events of the model. It depends only on SciMLBase.jl and SymbolicIndexingInterface.jl, plus a solver to solve it with.

The export needs Symbolics.jl to be loaded:

using Neuroblox, Symbolics

prob = ODEProblem(g, [], (0.0, 1000.0))
write_standalone("model.jl", prob)

On a machine with only a solver package installed:

using OrdinaryDiffEqVerner
include("model.jl")

prob = StandaloneModel.problem()
sol = solve(prob, Vern7())
sol[:g₊neuron₊V]

The states and parameters keep the names they have in the original problem, so symbolic indexing (sol[name], getp, setp) works on the exported problem as it does on the original. Besides problem, the module defines rhs!, u0, p0, state_names, param_names, observed_names, tstops and tspan (and noise! for a stochastic model).

How the model is exported

The export has two steps. symbolic_model traces the problem: it runs the problem's own right-hand side on symbolic states and parameters, which gives one symbolic expression per scalar state. write_standalone turns those expressions into Julia code and writes the file.

  • Every parameter of a blox or connection that is a real number becomes a parameter of the exported model. Other parameters (vectors, functions, Bools) and the structure of the graph are built into the equations with their current values.
  • Events are traced by running the event code of the blox and connections on the symbolic system and recording what it writes. An event with event_times is traced at each of those times and fires only then. Other events are traced with a symbolic time. Event code must be free of branches on the states and parameters, and may only change states and numeric parameters.
  • Computed properties become observed quantities of the exported model.
  • Callbacks passed as global_events are not supported.

Most of what cannot be exported faithfully raises an error that names the blox or connection, rather than producing a file that behaves differently from the simulation. The most common case is code that branches on a symbolic value (if V > θ ... end): write the branch with ifelse, or override the lowering as described below. A few cases are not detected; see Gotchas below.

Hiding the names

With obfuscate=true every state, parameter and observed quantity gets a generated name, so that the file does not say what its variables are. The name table, which maps the original names to the generated ones, is returned and can be written to a separate file:

table = write_standalone("model.jl", prob; obfuscate=true, name_table_path="names.tsv")

The equations and all values are still in the file, and its states are still grouped by blox type. Obfuscation hides what the variables are called, not what the model computes.

Overriding the lowering

Each of these functions has a default that reproduces the behaviour of the simulation. Add a method to change how a blox type, a connection between two blox types, or an event is exported. Inside these methods the states and numeric parameters of a Subsystem are symbolic.

FunctionOverrides
GraphDynamics.symbolic_subsystem_differential(sys::Subsystem{T}, input, t)the differential of blox of type T
GraphDynamics.symbolic_subsystem_noise!(vstate, sys::Subsystem{T}, t)the noise of blox of type T
GraphDynamics.symbolic_connection_input(conn, src::Subsystem{S}, dst::Subsystem{D}, t)the input a connection sends from blox of type S to blox of type D
GraphDynamics.symbolic_events(sys::Subsystem{T}), GraphDynamics.symbolic_events(conn, src, dst)the events of a blox type or of a connection, as a list of GraphDynamics.SymbolicEvent
GraphDynamics.is_symbolic_param(owner, name, value)which parameters become parameters of the exported model

For example, a stimulus that is switched on and off at fixed times can declare its events directly instead of having them traced:

function GraphDynamics.symbolic_events(sys::Subsystem{PulsesStimulus})
    [GraphDynamics.SymbolicEvent(; times = sys.times_on,  affect = [sys.I => sys.pulse_amp]),
     GraphDynamics.SymbolicEvent(; times = sys.times_off, affect = [sys.I => sys.baseline])]
end

Gotchas

The export cannot tell that these cases are unfaithful, so it raises no error for them. Check for them before exporting.

  • Random numbers drawn by event code. An event that draws random numbers when it fires, with rand(rng) on a generator stored as a parameter or with rand(), is traced by running it once per traced time. The numbers drawn then are written into the file as constants: an event at fixed times adds the same numbers in every run, and an event without fixed times adds one and the same number every time it fires. Tracing also draws from the generator, so the problem's later simulations draw different numbers than they would have. In Neuroblox the connection TAN => Matrisome is such an event. Random numbers drawn while the graph is built (connection patterns, Poisson spike times, background currents) are part of the problem and export correctly.
  • Ref parameters. If any blox in the graph has a parameter that is a Ref, every event that is traced (rather than declared with symbolic_events) fails with the error that it "changes the parameter" holding the Ref, even if no event touches it and the Ref belongs to another blox. Declare the events of the graph with symbolic_events, or keep Refs out of the parameters.
  • Other mutable parameters. Changes that event code makes in place to a parameter that is neither an array nor a Ref (a Dict, say) go unnoticed, and are missing from the export. Declare such events with symbolic_events.
