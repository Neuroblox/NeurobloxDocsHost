Utility functions

Blox are the basic components of neural circuits. For documentation of the kinds of blox available, please see the Blox documentation page. Internally these are represented as ModelingToolkit systems.

The following functions are used to query blox.

NeurobloxBase.get_exci_neurons — Function
get_exci_neurons(n::Union{GraphSystem, AbstractBlox})

Returns all excitatory neurons within a blox or graph.

  • If n <: Union{GraphSystem, AbstractComposite}, returns all excitatory neurons within the graph or composite blox.
  • If n::AbstractExciNeuron, returns a single-element vector [n].
NeurobloxBase.get_inhi_neurons — Function
get_inhi_neurons(n::Union{GraphSystem, AbstractBlox})

Returns all inhibitory neurons within a blox or graph.

  • If n <: Union{GraphSystem, AbstractComposite}, returns all inhibitory neurons within the graph or composite blox.
  • If n::AbstractInhiNeuron, returns a single-element vector [n].
Base.nameof — Function
nameof(blox)

Returns the name of blox without the namespace prefix.

See also namespaced_nameof and full_namespaced_nameof.

NeurobloxBase.namespaced_nameof — Function
namespaced_nameof(blox)

Returns the name of the blox, prefaced by its entire inner namespace (all levels of the namespace EXCEPT for the highest level). Namespaces represent the parent composite blox or graph that blox belongs to. E.g. the name cort1.wta2.neuron4 comes from a neuron neuron4 which belongs to wta2 (possibly a WinnerTakeAll blox) which in turn is part of cort1 (possibly a Cortical blox).

See also nameof and full_namespaced_nameof.

NeurobloxBase.full_namespaced_nameof — Function
full_namespaced_nameof(blox)

Return the name of the blox, prefaced by its entire inner namespace (all levels of the namespace INCLUDING for the highest level). Namespaces represent the parent composite blox or graph that blox belongs to. E.g. the name mdl.cort1.wta2.neuron4 comes from a neuron neuron4 which belongs to wta2 (possibly a WinnerTakeAll blox), which in turn is part of cort1 (possibly a Cortical blox), which finally is part of a circuit mdl.

See also nameof and namespaced_nameof.

Additionally there are several helpers for extracting useful information from solutions to simulations, such as the timing of spikes and the firing rate. Several of these are called by the plotting functions.

NeurobloxBase.detect_spikes — Function
detect_spikes(blox::AbstractNeuron, sol::AbstractSolution;
              threshold=nothing,
              tolerance=1e-3,
              ts=nothing,
              scheduler=:serial)

Find the spike timepoints of blox according to simulation solution sol. Return a SparseVector that is equal to 1 at the timepoints of each spike.

Keyword arguments: - threshold : [mV] Spiking threshold. Note that neurons like NeurobloxPharma.HHExciNeuron and NeurobloxPharma.HHInhiNeuron do not inherently contain a threshold and so require this threshold argument to be passed in order to determine spiking events. - tolerance : [mV] The tolerance around the threshold value in which a maximum counts as a spike. - ts : [ms] Timepoints in simulation solution sol where spikes are detected. It can be a range, a vector or an individual timepoint. If no values are passed (and ts=nothing) then the entire range of the solution sol is used.

NeurobloxBase.firing_rate — Function
firing_rate(blox::Union{AbstractComposite, Vector{AbstractNeuron}}, sol::AbstractSolution;
            transient=0, win_size=last(sol.t) - transient,
            overlap=0, threshold=nothing,
            scheduler=:serial, kwargs...)

Calculates the firing rate of blox. If blox is a composite blox or a vector containing multiple elements, then the average firing rate across all neurons in blox is returned.

Keyword arguments:

  • win_size : [ms] Sliding window size.
  • overlap : in range [0,1]. Overlap between two consecutive sliding windows.
  • transient : [ms] Transient period in the beginning of the timeseries that is ignored during firing rate calculation.
  • threshold : [mV] Spiking threshold.

See also frplot.

NeurobloxBase.inter_spike_intervals — Function
inter_spike_intervals(blox::AbstractNeuron, sol; threshold, ts)

Return the time intervals between subsequent spikes in the solution of a single neuron.

inter_spike_intervals(blox::AbstractNeuron, sol; threshold, ts)

Return the time intervals between subsequent spikes in the solution of a Blox. Outputs a matrix whose rows are the interspike intervals for a single neuron.

NeurobloxBase.flat_inter_spike_intervals — Function
flat_inter_spike_intervals(blox::AbstractNeuron, sol; threshold, ts)

Return the time intervals between subsequent spikes in the solution of a Blox. Concatenates the lists of interspike intervals of all vectors into a single vector.

NeurobloxBase.powerspectrum — Function
powerspectrum(cb::Union{AbstractComposite, Vector{AbstractNeuron}}, sol::AbstractSolution; sampling_rate=nothing, method=periodogram, window=nothing)

Calculate the power spectrum of the voltage timeseries for all neurons and/or neural masses contained in blox.

See powerspectrumplot for more information on the keyword arguments.

NeurobloxBase.voltage_timeseries — Function
voltage_timeseries(cb::Union{AbstractComposite, Vector{Union{AbstractNeuron, AbstractNeuralMass}}, sol::AbstractSolution; ts)

Return the voltage timeseries of all neurons and/or neural masses contained in blox. The output is a Matrix where each row is a separate neuron or neural mass and each column is a timepoint.

Keyword arguments:

  • ts : [ms] Timepoints at which the voltage values are evaluated in simulation solution sol. It can be a range, a vector or an individual timepoint. If no values are passed (and ts=nothing) then the entire range of the solution sol is used.
NeurobloxBase.meanfield_timeseries — Function
meanfield_timeseries(cb::Union{AbstractComposite, Vector{AbstractNeuron}, sol, state; ts)

Return the average timeseries of state variable state over all neurons contained in cb.

Keyword arguments:

  • ts : [ms] Timepoints at which the timeseries is evaluated in simulation solution sol. It can be a range, a vector or an individual timepoint. If no values are passed (and ts=nothing) then the entire range of the solution sol is used.

Parameter and Optimization Utilities

When fitting model parameters to experimental data or running optimization workflows, the following utilities build a ComponentVector from the current parameter and/or state-variable values of an ODEProblem and apply changes back without manually maintaining symbol-value lists.

NeurobloxBase.extract_vars — Function
extract_vars(prob, syms::AbstractVector{Symbol}) :: ComponentVector

Build a nested ComponentVector from a problem, carrying the current values for the given symbols. syms may contain a mix of parameter and state-variable accesses, e.g.:

julia> using NeurobloxBasics

julia> @graph g begin
           @nodes ho = HarmonicOscillator(;ω=23.0)
       end
GraphSystem(...1 nodes and 0 connections...)

julia> prob = ODEProblem(g, [], (0.0, 1.0));

julia> v = extract_vars(prob, [ho.ω, ho.ζ, ho.x])
ComponentVector{Float64}(g = (ho = (ω = 23.0, ζ = 1.0, x = 1.0)))

julia> v.g.ho.ω # Namespaced indexing
23.0

Symbols are sorted lexicographically to build the nested structure, so the order of fields in the returned ComponentVector may differ from the order of syms. For example, variables from the same blox are grouped together regardless of input order:

julia> v = extract_vars(prob, [nn1.V, nn2.V, nn1.m])
ComponentVector{Float64}(g = (nrn1 = (V = -65.0, m = 0.05), nrn2 = (V = -65.0)))

apply_vars is the 'inverse' of this operation, i.e. apply_vars(prob, v) will produce a new prob with new values for states and parameters corresponding to the entries of the ComponentVector.

NeurobloxBase.apply_vars — Function
apply_vars(prob, v::ComponentVector) :: ODEProblem

Remake prob with updated values from v. The ComponentVector may contain a mix of parameter and state-variable entries; they are separated automatically and applied via remake(prob; p=..., u0=...). Inverse of extract_vars.

julia> using NeurobloxBasics

julia> @graph g begin
           @nodes ho = HarmonicOscillator(;ω=23.0)
       end
GraphSystem(...1 nodes and 0 connections...)

julia> prob = ODEProblem(g, [], (0.0, 1.0));

julia> v = extract_vars(prob, [ho.ω, ho.ζ, ho.x]);

julia> prob2 = apply_vars(prob, v);

julia> v.g.ho.x = 3.0 # update a state
3.0

julia> prob2 = apply_vars(prob, v); # produce a new problem object

julia> getsym(prob2, ho.x)(prob2) # the value of x is updated
3.0

The original problem is left unchanged:

julia> getsym(prob, ho.x)(prob)
1.0
NeurobloxOptimization.optimize_state — Function
optimize_state(data, state_sym, param_syms, prob; solve_alg, opt_alg, solve_kwargs=(;), opt_kwargs=(;), adtype=Optimization.AutoForwardDiff())

Optimise parameters param_syms of prob so that the simulated trajectory of state_sym (or multiple states) best matches the measurements in data in a least-squares sense.

Arguments

  • data: Source of target measurements. Two accepted forms:
    • SciML solution (result of solve): times come from data.t; state values are accessed via symbolic indexing data[sym].
    • Tables.jl-compatible table (e.g. a Vector of NamedTuples, a DataFrame, …): must have a column named :t for time and one column per state symbol. Column names must match state_sym exactly — Neuroblox state symbols are namespaced (e.g. nm.x returns :g₊nm₊x). Example: [NamedTuple{(:t, nm.x)}((0.0, 1.0)), …].
  • state_sym::Union{Symbol, AbstractVector{Symbol}}: State variable(s) to match, e.g. nm.x or [nm.x, nm.y].
  • param_syms::Union{Symbol, AbstractVector{Symbol}}: Parameter(s) to optimise, e.g. nm.ω or [nm.ω, nm.ζ].
  • prob: ODEProblem built from a Neuroblox graph. Left unchanged.

Keyword Arguments

  • solve_alg (required): ODE solver, e.g. Tsit5() from OrdinaryDiffEqTsit5.
  • opt_alg (required): Optimisation algorithm, e.g. LBFGS() from OptimizationOptimJL.
  • solve_kwargs: Extra keyword arguments forwarded to each inner solve call, e.g. (abstol=1e-8, reltol=1e-8). The saveat grid is taken from data automatically; pass an explicit saveat here only to override it.
  • opt_kwargs: Keyword arguments forwarded to the optimiser solve call, e.g. (maxiters=500,) or (f_tol=1e-6,).
  • adtype: AD backend (default Optimization.AutoForwardDiff()). Requires ForwardDiff to be loaded; compatible with Tsit5().

Returns

A named tuple (; result, prob):

  • result: Optimization.solve result; fitted values in result.u (a ComponentVector).
  • prob: Remade ODEProblem with the optimised parameters applied.

Examples

using NeurobloxBasics, NeurobloxOptimization
using OrdinaryDiffEqTsit5: Tsit5
using OptimizationOptimJL: LBFGS

@graph g begin
    @nodes nm = HarmonicOscillator(; ω=1.0, ζ=0.5)
end
true_prob = ODEProblem(g, [], (0.0, 10.0))
true_sol  = solve(true_prob, Tsit5())   # SciML solution used as data

# Single state, single param — saveat taken from true_sol.t automatically
res = optimize_state(true_sol, nm.x, nm.ω, true_prob;
                     solve_alg=Tsit5(), opt_alg=LBFGS())

# Multiple states and params simultaneously
res = optimize_state(true_sol, [nm.x, nm.y], [nm.ω, nm.ζ], true_prob;
                     solve_alg=Tsit5(), opt_alg=LBFGS())

# Tables.jl table (e.g. from a NamedTuple array, DataFrame, or CSV)
data_tbl = [NamedTuple{(:t, nm.x)}((t, v))
            for (t, v) in zip(true_sol.t, true_sol[nm.x])]
res = optimize_state(data_tbl, nm.x, [nm.ω, nm.ζ], true_prob;
                     solve_alg=Tsit5(), opt_alg=LBFGS(),
                     opt_kwargs=(maxiters=500,))

res.result.u    # fitted ComponentVector
res.prob        # remade ODEProblem with optimised parameters
